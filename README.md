# blue_gear_group3 — 2056 能源分配模擬器

> 能源過剩之後，真正的問題不是「能源夠不夠」，而是「誰有權決定能源怎麼分」。

這個 prototype 是一個可以互動的模擬器。在同一個情境下，它比較四種能源分配制度的結果，並用「價值權重」說明一件事：**實驗只能告訴我們會發生什麼，不能決定什麼值得追求。**

## 畫面

- **我的資料（左側）**：居住地區、職業／產業、特殊需求、本期已用額度（預設等於基本需求，上限為我分配到的總額）
- **我的能源**（固定使用 D 兩層混合制）：看「我分配到的總額／已用額度／已購買額度／剩餘額度／已回收額度」。「來源」條分為分配額度（深藍）、額外需求（橘）、購買的額度（淺藍）；「使用」條顯示已用、剩餘與已回收（灰色虛線框）
- **上一個月／下一個月（左下）**：
  - 按「下一個月」會把本月數值**固定下來**成為紀錄，並進入新的月份：下個月的分配總額 = 本月分配總額 + 本月購買額度的一半，「額外需求」逐月累加（第 1 月買 1 → 第 2 月 +0.5；第 2 月再買 1 → 第 3 月共 +1）；已用、已購買、已回收歸零；擁有金額保留
  - 按「上一個月」只能**查看**過去月份的紀錄（唯讀）：不能回收、購買、儲值或修改資料。查看時按「下一個月」會往後翻，翻到最後就回到目前月份，目前月份的數值不會被重設
  - 每個月只會固定一次；第一個月時「上一個月」是灰色、不能按
- **額度交易**：點選其中一個選項後，才會出現輸入欄與總價計算（選取後才展開；回收、購買的成功或失敗提示顯示在「額度交易」標題旁）
  - **回收剩餘額度**：輸入回收額度 → 顯示「回收額度 × 回收單價 = 回收總價」→ 按「確定回收」。回收額度大於剩餘額度時顯示「回收失敗，剩餘額度不足」；否則顯示成功提示，從剩餘額度扣除並累計到「已回收額度」（分配總額不變）
  - **購買額外額度**：輸入購買額度 → 顯示「購買額度 × 購買單價 = 購買總價」→ 按「確定購買」。顯示成功提示，累計到「已購買額度」並增加剩餘額度（分配總額不變）
  - 右上角顯示**目前擁有金額**（初始 5 元）：回收加錢、購買扣錢；按「儲值」可輸入金額或用 +5／+10／+50 快速加值。購買總價超過擁有金額時，顯示「擁有金額不足，請先儲值或降低購買額度」，不會執行
  - 回收單價 8 元、購買單價 10 元，差額留在公共能源池；輸入框按 Enter 也可以送出

模擬情境固定為：能源總量 = 基本需求的 1.5 倍；D 制度最低能源權 100%，過剩能源一半給產業（可在 `js/app.js` 的 `SCENARIO` 修改）。

不用安裝任何套件，也不用網路。

## 四種制度

| 制度 | 規則 |
|---|---|
| **A 平均制** | 每個人分一樣多（依人口比例） |
| **B 需求制** | 先依優先等級（3 = 醫院、災區 → 2 = 偏鄉、高寒 → 1 = 一般）滿足基本需求；有剩再按需求比例分 |
| **C 效率制** | 把能源給邊際產值最高的地方，讓總產值最大（等邊際原則） |
| **D 兩層混合制**（本組提案） | **第一層**：最低能源權（基本需求的 X%），用需求制保障，不能拿來實驗。<br>**第二層**：剩下的過剩能源，一部分當公共能源平均分，另一部分當產業能源用效率制分 |

D 制度對應我們的結論：基本能源用需求制，公共過剩能源用平均制，額外產業能源用效率制，也就是 Ostrom 的多中心治理，不同用途由不同制度管理。

## 模型假設

所有數值都是抽象單位，只用來比較制度，不代表真實數據。

- 每個地區有：人口 `pop`、人均基本需求 `need`、產值係數 `prod`、優先等級 `priority`
- 基本需求 = `pop × need`
- 產值函數：`Y = prod × pop × ln(1 + 能源 / pop)`，邊際效益遞減
- 能源總量以「未受事件影響的基本需求總量」為基準。事件（寒流、地震）會提高需求，但能源總量不變，所以會造成壓力

## 個人視角的計算方式

一個人相對全體可以忽略，所以個人資料不改變地區總量，只決定這個人在地區內分到多少：

| 能源來源 | 個人分到 | 受什麼影響 |
|---|---|---|
| 需求制部分（B 全部、D 第一層） | 地區分配 ÷ 地區基本需求 × 我的基本需求 | 特殊需求會提高份額 |
| 平均制部分（A 全部、D 公共能源） | 地區人均 | 不受個人資料影響 |
| 效率制部分（C 全部、D 產業能源） | 地區人均 × 職業係數 | 產業 2.0、一般 1.0、公共服務 1.0、學生退休待業 0.5 |

- **我的基本需求** = 地區人均需求 + 特殊需求加計（維生醫療設備 +1.5、高齡或行動不便 +0.4、照顧嬰幼兒 +0.3）
- **我分配到的總額** = 制度分配（購買與回收都不改變總額）
- **剩餘額度** = 總額 + 已購買額度 − 已用額度 − 已回收額度（負值代表超用）
- 交易規則在 `js/model.js`：`TRADE`（回收單價、購買單價、初始擁有金額）與 `trade()`（檢查額度、產生成功／失敗訊息）

## 評估指標

| 指標 | 意義 |
|---|---|
| 基本需求滿足率 | Σ min(分配, 需求) / Σ 需求 |
| 最差地區滿足率 | 最慘的地區基本需求被滿足多少（對應 Rawls 的「最不利者」觀點） |
| 基本需求未滿足人口 | 有缺口的地區總人口 |
| 吉尼係數 | 以「需求調整後人均能源」（分配 / 基本需求）計算的人口加權吉尼係數。需求高的地區分得多，不算不公平 |
| 總經濟產值 | 各區產值加總 |

## 價值權重

每個指標先在各制度之間正規化到 0–100，再依權重加總。內建四組價值觀：效率優先、平等優先、保障優先、均衡。可以看到，**同一組實驗結果，換一組價值觀，「最好」的制度就不同**。所以權重應該由全球能源公民議會決定，不是由模型或工程師決定。

## 可以延伸的方向

- 公民議會投票：抽選議員，對最低能源權額度和評估指標權重投票，結果回饋到模擬器
- 申訴與退出機制：參與者可以退出實驗，觀察對結果的影響
- 時間維度：模擬多年、儲能與輸電限制造成的局部稀缺
